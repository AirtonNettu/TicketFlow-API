## 2024-07-28 - [Information Leakage in Error Handler]
**Vulnerability:** The central error handler (`src/middlewares/errorHandler.js`) blindly used `err.message` for all errors regardless of HTTP status code or error type, allowing unexpected system errors (e.g., file system access errors) to leak internal state or file paths to API clients.
**Learning:** Defaulting to `err.message` across the board in a unified error handler is a security risk. Operational errors (custom exceptions like `ApiError` with status < 500) typically have safe messages meant for the user. Non-operational or system errors (status >= 500) can contain sensitive internal details generated by Node.js or third-party libraries.
**Prevention:** In unified error handling middlewares, explicitly distinguish between operational errors and system errors. Only expose the `err.message` to the client for known operational errors. For system errors, override the message with a generic, safe response like "Internal Server Error" while logging the actual error stack trace internally (`console.error`) for observability and debugging.
