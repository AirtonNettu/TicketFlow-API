## 2024-11-23 - [Stored XSS in Vanilla JS with innerHTML]
**Vulnerability:** Found a Stored Cross-Site Scripting (XSS) vulnerability in the frontend application (`public/app.js`). User input (`titulo` and `descricao`) from the tickets API was directly injected into the DOM via `.innerHTML` without output encoding.
**Learning:** The project's convention is to use vanilla JavaScript without modern frameworks. Modern frameworks usually protect against XSS automatically by encoding interpolation (e.g. JSX or Vue templates). However, directly setting `.innerHTML` in vanilla JS with unsanitized data from a REST API is highly dangerous because script tags and malicious attributes can execute. The data was stored raw in the backend JSON database and only became dangerous upon frontend rendering.
**Prevention:** Always implement output encoding (e.g. an `escapeHTML` function) directly before rendering data to the DOM via `.innerHTML` in vanilla JS. Avoid double-escaping bugs by ensuring that raw text is stored in the database, and only output is escaped on the frontend.
